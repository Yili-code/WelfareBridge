# 使用者介面（福利補助導覽）

設計依 [welfare-ui4](https://hytncu.github.io/welfare-ui4/)：粗黑框、硬陰影、芥末黃／藍／薄荷配色，四個分頁加上一般／長者模式。
資料改接真正的官方補助資料庫與資格比對，只顯示使用者需要的資訊。

## 頁面

| 分頁 | 內容 | 程式 |
| --- | --- | --- |
| 查詢補助與服務 | 沒有資料卡時的建立邀請、搜尋、快速篩選、左側篩選（地區／補助領域／補助類型／適用對象）、排序（比對結果／截止日／名稱／公告時間）、卡片列表（每次顯示 20 筆）、「只看我可能符合的」 | `src/welfare/SearchPanel.tsx`、`search.ts`、`BenefitCardView.tsx` |

長者模式把整頁字級放大到 21px、單欄排版、隱藏次要資訊；選擇會記在瀏覽器。手機寬度下資料卡小視窗改為全螢幕。

## 讓使用者少做一步的設計

- **補這幾題**：`/api/public/match` 另外回傳 `questions`——統計「需要進一步確認」的補助最常缺、而且能直接回答的資料（是非、選項、數字、縣市），取前 3 題（`quick_questions`）。使用者點答案就寫進 `assistantAttributes`（標示為使用者確認），重新比對；「不確定」也會記下，不再重複問。最小子女年齡多一個「沒有未成年子女」選項（記為子女 0 人）。
- **截止日**：卡片與詳情顯示「今天截止／還有 N 天截止（7 天內紅色、30 天內黃色）」「M 月 D 日截止」「隨時可申請」，日期以使用者裝置的當地日期計算（`deadline.ts`）；已過期不標示。排序「依截止日」＝快截止的在前、隨時可申請其次、沒寫期限的最後。
- **收藏與提醒**：收藏存在瀏覽器（所有資料卡共用）。收藏的補助 7 天內截止時，查詢與資料卡頁上方顯示提醒，「今天不再提醒」當天有效。
- **列印／存成 PDF**：結果頁列印「可能符合」全部＋「需要進一步確認」前 20 項；收藏清單列印全部。列印版只有補助名稱、比對狀態、機關、金額、截止、申請方式、還缺的資料、官方網址與勾選欄（已詢問／已備齊文件／已送出申請），網頁其他部分列印時隱藏（`PrintSheet.tsx`、`@media print`）。

## 不顯示給使用者的資訊

前台只呼叫 `/api/public/*`（`backend/app/api/public.py`），後端只回傳卡片與詳情需要的欄位；
抽取證據、規則信心分數、分類依據、本地 AI 狀態、爬蟲與處理狀態、JSON 原始資料都不會送到使用者的瀏覽器，
只留在 `/api/benefits` 與後台資料中心。

- 錯誤訊息改成使用者語句（「補助資料服務暫時無法使用，請稍後再試」），不顯示 HTTP 代碼或模型設定
- 金額範圍差距超過 20 倍（多半混進資力門檻或年度總額）時不硬寫數字，改顯示「金額依核定」
- 附件名稱只有「pdf」「一」這類字時顯示「附件 N」

## 聊天小幫手 → 資料卡 → 主畫面

```
使用者回答  →  POST /api/assistant  →  guidance（解析回答、依比對結果挑下一題）
                                         └→ learned：對話中確認的資料（屬性、值、顯示文字、可選值）
前端 mergeLearned  →  profile.assistantAttributes（寫進資料卡）
                   →  toMatchingProfile 套用（優先於問卷推得的值）
                   →  POST /api/public/match 重新比對  →  查詢頁標示、資料卡統計、詳情原因一起更新
聊天視窗只顯示：「已寫進資料卡：身心障礙證明：否」＋「需進一步確認 223 → 196 項」
```

- 每輪都以資料卡為準送出資料；在資料卡改掉或刪除的值，下一輪對話就不會再用舊值
- 從自由輸入的文字判讀出的值（例如「我有兩個小孩」）標示「從對話內容判讀，請確認」，比對時仍視為未確認
- 追問完全由資格規劃器決定（`backend/app/matching/planner.py`，資格骨幹缺的欄位優先），**不需要本地 AI**，每輪約 1～5 秒；只有「整理需求登記給承辦人員」會用本地 AI 寫摘要
- 使用者明確說「幫我找…」時，關鍵字會帶到查詢頁搜尋，結果顯示在畫面上而不是聊天視窗
- 沒有資料卡時也能聊，但會提示「先建立資料卡，回答才能保存」

## 訴求專區

訴求與附議存在 `data/welfare.sqlite`（`src/lib/server/demands.mjs`），和小幫手的需求登記（只給承辦人員看）分開：

| API | 說明 |
| --- | --- |
| `GET /api/demands?voter=…` | 公開清單（不含個人資料） |
| `POST /api/demands` | 提出訴求；提出者自動算第一則附議 |
| `POST /api/demands/{id}` | 附議；同一個瀏覽器對同一則只算一次（瀏覽器隨機識別碼） |
| `PATCH /api/demands/{id}` | 後台密碼：設為蒐集中／已認領／已實現，填認領機關與處理結果 |

後台 `/admin` 的「訴求專區」分頁可以認領與回報。

限制：附議以瀏覽器識別碼防重複，清除瀏覽器資料或換瀏覽器可以再附議一次；沒有速率限制。上線前若要防灌票，需要登入或 IP 限流。

## 舊頁面

`/dashboard`、`/my-benefits`、`/my-scholarships` 導回首頁（`next.config.ts` 的 `redirects`）。
