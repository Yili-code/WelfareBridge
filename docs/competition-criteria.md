# 決賽評分對照

依資訊服務創新應用大賽（大專校院）決賽評分項目整理。每項對照本系統的做法、可展示的位置與還需要注意的地方。
比賽辦法以官方網站為準：https://innoserve.tca.org.tw/Rules/Detail?category=College

## 資訊應用組（創新 30、實用 15、穩定 15、擴充 15、系統文件 15、說明展示 10）

| 評分項目 | 本系統的做法 | 展示位置 | 風險與備註 |
| --- | --- | --- | --- |
| 創新性 30% | 把分散的官方補助整理成可判斷的規則，每個條件附原文證據；小幫手依「最能確認資格」挑題；可用一句話提出需求；中途改提別的需求會直接換題 | 首頁搜尋、資料卡、小幫手 | 規則引擎與 AI 分工要講清楚 |
| 實用性 15% | 930 筆補助、多個縣市；收藏、截止提醒、列印、長者模式 | 首頁、收藏、長者模式 | 比對結果是初步導引，要說明以官方公告為準 |
| 穩定性 15% | 後端約 177 項、前端 24 項自動測試；AI 離線時比對與追問仍可用；回答讀不出來時第二次自動跳過，不會卡在同一題 | 現場示範；`npm test`、`pytest` | 現場要確認伺服器與本地 AI 在線 |
| 擴充性 15% | 來源以 `sources.yaml` 設定；屬性登錄表 | `docs/architecture.md` | |
| 系統文件 15% | README、架構、資料模型、資格媒合設計、整合驗證、決賽講稿 | `docs/` | 提交前要確認文件與畫面一致 |
| 說明展示 10% | 6 分鐘講稿與時間表 | `docs/demo-script.md` | 同時報名兩組，要簡報兩次 |

## 教育開放資料組（開放資料使用度 40、創新 25、實用 25、說明展示 10）

| 評分項目 | 本系統的做法 | 風險與備註 |
| --- | --- | --- |
| 教育開放資料使用度 40%（數量與程度） | 教育部圓夢助學網、主管法規、青年發展署等教育部官方網站資料，爬取後轉成可比對的規則（127 筆教育類補助） | **主要弱點**：這些是爬取的網頁，不是政府資料開放平臺的資料集；系統目前沒有使用 data.gov.tw 的教育部資料集，評審可能給低分 |
| 創新性 25% | 獎助學金資格規則化，附原文證據；小幫手只問最能確認資格的題目 | |
| 實用性 25% | 學生資料卡 → 獎助學金比對，列出缺哪些條件 | |
| 說明展示 10% | 見 `docs/demo-script.md` | |

## 規則裡要留意的地方

- 決賽 11/7 在臺大綜合體育館；每組現場說明約 6 分鐘、詢答約 7 分鐘。
- 辦法裡有關於 AI 模型來源的條款（開源 AI 模型應用組明確限制中國機構開發的核心模型）。本系統的小幫手使用 Google Gemma 4；`data/demo/seed_v2.json` 記錄部分補助規則是用 `qwen2.5:7b` 抽取的，若評審詢問要誠實說明，並可用 Gemma 重跑。
