# Demo 講稿（v2）

## 0. 一句話

「所有資料都是從官方網站爬回來的原文，先用語料統計出來的關鍵字篩選分類，再抽成可判斷的規則；抽不出來的由本地 AI 填，但每一個值都要能指回原文，指不回去的就進不了資料庫。」

## 1. 資料中心（/data-center）

1. 統計卡：補助總數／去重／開放中／彙整頁、今日新增、待人工確認、本地 AI 已補齊（右上角顯示 Ollama 是否在線與模型名稱）、官方來源數、原始文件依處理狀態（含 filtered_out / skipped 的原因）、服務提供者名單筆數、登錄表版本、關鍵字統計摘要。
2. 領域 badge：教育、長期照顧、社會福利、勞工就業、住宅、身心障礙、醫療健康——每個領域的筆數都來自資料庫。
3. 爬蟲狀態：24 個來源，每個顯示官方驗證方法、頁面數與略過數、最近執行、原始文件與補助數；按「執行全部爬蟲」示範背景工作。
4. 原始文件清單：切到 `skipped` 看銀行登入頁、服務地圖、統計表的略過原因；切到 `filtered_out` 看關鍵字分類器擋掉的頁面與命中的負面詞。
5. 篩選「長期照顧」領域 → 點「臺北市身心障礙者生活補助」或「長期照顧交通接送服務」。

## 2. 明細頁

1. 原始資料：原文、爬取時間、content_hash、來源網址；classification 顯示命中的訊號詞與類別分數。
2. 標準 Schema：給付形式、金額與週期、申請期間（隨到隨辦）、核發方式、名額、申請管道／文件／是否需公所證明、義務、互斥、可續領、目標族群；完整 JSON。
3. 資格規則：每條規則的屬性（登錄表 id 與中文）、operator、值、群組（`alternative_1` 代表「符合下列條件之一」）、角色（必要／排除／加分）、信心、推定、抽取方式（結構化欄位／規則／本地 AI）、原文摘錄。
4. 條件句：每一句原文條件的狀態——規則對到、AI 對到、程序條款、仍需人工（complex）。
5. 本地 AI：模型名稱、處理時間、接受了哪些值（附摘錄）、拒絕了哪些（原因：摘錄不在原文／數值不在摘錄／屬性不在候選）。
6. 來源：來源驗證方法、related_records（同一公告的其他來源）、附近的服務提供者（長照類）。

## 3. 屬性登錄表（/registry）

- 80+ 個屬性依命名空間分組：型態、單位、領域、敏感度、硬過濾、推導公式、種子別名、語料統計別名、被幾條規則使用。
- 類別樹（8 領域 42 類別）與身分本體（低收入戶 ⇒ 清寒 ⇒ 弱勢學生）。
- 關鍵字表：來源 = 語料統計（mined），每個詞的權重；報告連結 keyword-report.md 有 z 分數與文件頻率。

## 4. 我的補助（/my-benefits）

1. 選需求類型「急需一筆錢」，勾「不想面試」。
2. 快速輸入：「我是基隆人，海洋大學資工大二，平均82分，低收入戶，學費繳不出來」→ 系統理解表（每個值附你的原話）→ 動態追問（例如就讀部別、操行成績）。
3. 開始比對 → 三張卡（最有把握／金額最高／最省力）、建議申請組合（互不衝突）、可申請清單（每張卡：為什麼推薦、注意事項、符合／缺少／不符合／需確認的條件、補充資料後自動重比對、不感興趣＋原因）。
4. 換一個情境：「我爸70歲住台北，中度身障，長照評估是第5級，需要人照顧」→ 需求類型自動變「需要照顧服務」→ 長照與身障類補助進入推薦，教育類進入「其他」。
5. 展開「目前不符合」看被排除的原因（例如戶籍縣市不符）；推定條件不會造成不符合，只顯示「請確認」。

## 5. 可信度的證據

- 每筆補助：source_url、crawl_time、content_hash、原文全文。
- 每條規則：原文摘錄；驗證器移除的規則列在 review.reasons。
- 每個 AI 填的值：摘錄 + 接受／拒絕紀錄。
- 關鍵字：docs/generated/keyword-report.md 可重現。
- 測試：`python -m pytest`（52 個測試，fixture 為真實官方頁面存檔）。
